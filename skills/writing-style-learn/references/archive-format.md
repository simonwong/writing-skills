# 风格档案格式

风格档案里 style.md、default.md、类型文件和 candidates.md 的骨架、每节放什么，以及单条规则的格式和放哪。花括号里换成实际内容；`<改前>` `<改后>` `<亲笔>` 是标签，照写。节标题下的「用法：」一行写这一节在写稿时怎么用，照骨架原样写，不改。

## style.md

所有体裁通用的写法。五节都要建，没有内容的节也留着节名，按下面的顺序排。

```markdown
# 个人风格

## 作者与读者

用法：写稿的背景。

{作者：身份、反复表过的立场}

{读者：怎么称呼、默认懂到什么程度、希望读完能做什么}

## 口头习惯

用法：要表达这个意思时，用这里的说法；不为了像作者而多用。

## 标点和排版

用法：必须遵循，不符合就是错。

## 讲事和解释

用法：遇到这个场景时照这样写；材料不适合时换个写法。

## 禁用词表

用法：必须遵循，不符合就是错。

- {说法}：{改成什么，或「删掉」}
```

| 节 | 放什么 | 写成 |
| --- | --- | --- |
| 作者与读者 | 作者是谁、以什么身份写、反复表过的立场；怎么称呼读者、默认读者懂到什么程度、希望读者读完能做什么。某一篇对谁有用，写稿时按材料定。这一节是写稿时定说法的背景：作者身份体现在怎么讲、讲什么上，正文只在材料需要时交代一次，不反复写「我作为开发者」这类话。 | 两段话，先写作者，再写读者。不分条。 |
| 口头习惯 | 作者顺手就会写的说法和句式：语气词、表态词、口头禅、连词、画外音、惯用的起句和收尾。只收作者亲手写的句子和手改，不从旧稿统计。 | 规则。标题写说法本身，如「等等」「我觉得」；句式写它的样子，如「画外音」。 |
| 标点和排版 | 只看字符就能判对错的写法：标点、空格、中英文混排、大小写。 | 规则。标题写管的对象，如「中英文混排」「句首小写」。按外部规范排版的，在做法里给链接。 |
| 讲事和解释 | 一件事先说什么、带上什么、怎么收；怎么下判断、给推荐；怎么称呼一个对象，如全文一个叫法、写中文还是英文。 | 规则。标题写场景，如「引出案例」「几种做法」「叫法」。 |
| 禁用词表 | 作者删掉过、写稿时容易冒出来的词和短语。 | 一行一条，写成 `- 说法：改成什么`，没有替换的写「删掉」。 |

## default.md

路径 `genres/{体裁英文短名}/default.md`，写这个体裁和 style.md 不同的地方。一级标题和「适用」必写；其余各节没有内容时不建，建了就按下面的顺序排。

```markdown
# {体裁名}

适用：{这个体裁指什么、发在哪里}

## 语气

## 结构

用法：参考，可以按内容调整。

1. {这一部分写什么}

## 讲事和解释

用法：遇到这个场景时照这样写；材料不适合时换个写法。

## 排版

用法：必须遵循，不符合就是错。

## 固定表达

用法：有对应位置时照写。

## 类型

- [{类型名}]({类型英文短名}.md)：{适用}

## 范文

- [{范文标题}](examples/{范文英文短名}.md)：{学什么，一句}
```

| 节 | 放什么 | 写成 |
| --- | --- | --- |
| 语气 | 这个体裁和 style.md 不同的语气：多正式、多热情、节奏快慢。 | 一两句。 |
| 结构 | 一篇从头到尾的推进。 | 按顺序编号，每步一行。 |
| 讲事和解释 | 只在这个体裁成立、要靠判断的写法：放什么、放多少、怎么讲。 | 规则。标题写场景。 |
| 排版 | 只在这个体裁成立、看版式就能判对错的写法：段落、小标题、列表、引用块。 | 规则。 |
| 固定表达 | 这个体裁固定出现的开头、收尾和固定文字，如结束语、参考链接。 | 规则。 |
| 类型 | 这个体裁下的类型，写稿时按这里选。 | 每项一个链接和一句适用。 |
| 范文 | 这个体裁通用的范文。 | 每项一个链接和一句学什么。 |

## 类型文件

路径 `genres/{体裁英文短名}/{类型英文短名}.md`，写这类文章和 default.md 不同的地方。一级标题和「适用」必写；其余各节没有内容时不建，建了就按下面的顺序排。

```markdown
# {体裁名}：{类型名}

适用：{这类文章对谁有用、什么材料选这个类型}

{语气、结构、讲事和解释、排版、固定表达、范文各节，写法同 default.md}
```

不列类型。范文只列这个类型的。

## candidates.md

还没定的写法。开头照下面写，条目追加在后面。

````markdown
# 候选

还没定的写法，不用于写稿。条目追加在文件末尾，照下面的格式写；`<改前>` `<改后>` 各占一行，内容照原样换行。

```
### {体裁} · 手改
来源：{稿件标题或路径}
背景：{这句在稿子里的位置，初稿为什么这么写}

<改前>
{改之前的句子}
</改前>

<改后>
{作者改后的句子}
</改后>

### {体裁} · 原话
来源：{稿件标题或路径}
原话：{作者说的话}
```
````

手改用和规则相同的 `<改前>` `<改后>` 标签，升级成规则时原样搬过去。

## 规则

规则写在 style.md 的「口头习惯」「标点和排版」「讲事和解释」，以及 default.md 和类型文件的「讲事和解释」「排版」「固定表达」下面，跟在「用法：」一行后面。其余各节按上面各表写成段落、列表或链接。

````markdown
### {这条规则管的对象或场景}

{做法：怎么做、到哪为止，1～3 句}

原因：{作者说过的原因}
适用：{用在哪里}

背景：{为什么这么改，或读懂这句要的上下文}

<改前>
{改之前的句子，照原样}
</改前>

<改后>
{作者改后的句子，照原样}
</改后>

背景：{……}

<亲笔>
{作者自己写的句子，照原样}
</亲笔>
````

示例：

````markdown
### 引出案例

第一句就说案例是什么、能做什么。

背景：一节的第一句。初稿第一句是过渡，第二句才说出案例，读者读完第一句还不知道这一节讲什么。

<改前>
图画在纸上之后，还得落成能跑的东西。Claude Code 的动态 workflow 是一个现成的例子。
</改前>

<改后>
Claude Code 的动态 workflow 是一个很好的案例，可以根据任务生成不一样的图（工作流）。
</改后>
````

- **标题**写这条规则管的对象或场景，写成名词或一个说法，如「引出案例」「叫法」「等等」，不总结做法。标题是规则名，同一个文件里不重名。文件位置已经交代的条件（体裁、类型）不写进标题。
- **做法**写完整的写法，1～3 句，并列的几项列成列表：用哪个词、放在哪、写成什么样、到哪为止，材料里的改稿动作（删掉、去掉、改成）换成改完后的写法。作者固定用的一组词写在这里。不用「直截了当」「自然」这类形容词。
- **原因**只写作者说过的，一行；作者没说过时不写。
- **适用**写规则只在哪些位置或条件下成立，一行。做法和文件位置已经说清用在哪的不写；要写时位置写具体，如「全文最想表态的地方」，不写次数，也不写「少用」「偶尔」。缩窄规则时改这一行。篇幅和密度写成判断时看什么，如「一段在手机上读着太长时，在意思转折处分开」。
- **例子**跟在规则后面，每组二选一：手改写 `<改前>` 加 `<改后>`，亲笔写 `<亲笔>`。前面可以加一行「背景：」，写为什么这么改，或读懂这句要的具体上下文，如这句在一节的什么位置；都没有时不写。不写出自哪篇稿子，写稿的 agent 找不到原稿。标签各占一行，内容照原样换行，一个字都不改；亲笔开头接不上时，往前多截一两句。每条最多两组，例子都要符合做法，做法也不比例子说得更宽。没有真实例子时不写例子。
- 一条规则只管一件事；做法里出现两个能分开判断的做法时，拆成两条。
- 一节里的规则按加入的先后排。

## 放哪

先定文件：

- 只在某个类型里成立的，放该类型文件。
- 依赖这一体裁的位置、篇幅、分段或平台的，放该体裁的 default.md。
- 其余放 style.md。
- 类型文件和 default.md、default.md 和 style.md 说法不同时，下一层只写不同的那部分。

再按上面各表的「放什么」定节。default.md 和类型文件里，固定出现的文字放固定表达，看版式就能判对错的放排版，其余放讲事和解释。拿不准放 style.md 哪一节时，依次问：

1. 这个说法什么场合都不用？放禁用词表。
2. 只看字符就能判对错？放标点和排版。
3. 把里面的词换掉，规则就不成立？放口头习惯。
4. 其余放讲事和解释。

都不合适时放最接近的一节，并告诉作者。
