# 表达

说话位置随材料定：亲历、转述、观察、判断、疑问和感受各按本来面目说，句子都是作者自己在说话。作者的参与体现在关注什么、选了哪些材料、怎样说、认可哪些判断。

## 说话方式

- 直接进入事情：需求、操作、结果、作品或现象。省去空泛的时代背景；热点和近期变化本身值得讨论时，直接作为主题。
- 分清实测、转述和体感：实测写做了什么、看到什么，体感就说是体感。
- 判断直接说，后面紧跟数字、对比、案例或原话；有边界就给边界，不确定只落在局部具体处。

  > 这套记录方式适合一个人用。几个人同时改一个文件就会冲突，得靠 git 手动合并。

  > 换了 harness 通过率上去了，哪个 hook 起的作用还没拆开测。

- 数字带条件：多少、在什么范围、和什么比。没有口径的倍数改写成变化本身。

## 转述别人的内容

直接写内容本身，句子是陈述句，句首直接是事，「作者说」「报告称」「文中提到」这类填充省去。用原文的口径，原文没给数字来源就不补。原文自带的形容和评价（圆满、深远、终于）留在原文里。需要交代归属时用作者的句式：来源方自报的写「官方给的数据是」「团队自己的说法是」；别人的测试把条件和范围放进句子里。原文视角的「我们」换成第三人称主体（团队、产品名）或去掉主语；原作者的动作也直接写事，主语用团队或产品名。

## 反应词

默认没有反应词。材料自带反应或用户要求带时用一个：材料里的词照用；用户没给词时，用风格档案里作者用过的，没有档案就不加。

紧接引起反应的那件具体事，强度对应事情的分量。
