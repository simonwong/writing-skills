# 写作风格入档与整理

把作者本人写且认可的文字提炼成规则、类型和范文，写进风格档案，让写稿时写出作者自己的说法。规则只收作者和模型默认写法不同的地方。

## 依据

档案只收三类依据：

- **手改**：作者亲手改的句子，或作者给出了确切的改后文字（如「并不新改成并不新鲜」）。改前可以是 agent 写的。
- **原话**：作者自己说出的写作偏好，包括作者逐条确认过的已有规则，以及只给方向、没有改后文字的修改意见。
- **亲笔**：作者自己写、认可的句子和段落。作者给整篇亲笔稿时，只有作者圈出的段落和指出的写法算依据，其余部分只作线索。

agent 写的段落、AI 代写后未经作者认可的稿件、别人转述而找不到作者原话或手改支撑的结论、阅读量和数据表现，都只作线索，用来向作者提问。

## 规则

规则的格式、各文件的骨架、每节放什么、放哪一节，见 [archive-format.md](references/archive-format.md)。

规则不标强度：放进哪一节，就按那一节标题下的「用法：」用。「用法：」照骨架原样写，新建一节时带上。

## 类型文件

类型是一种体裁里结构固定、会反复写的一类文章，如长文的踩坑教程、推文的转推。作者认可的亲笔稿结构和 default.md「结构」明显不同，且作者确认这类文章还会写时，按 archive-format.md「类型文件」一节新建 `genres/<体裁>/<英文短名>.md`；在 default.md「类型」一节加一行 `- [<类型名>](<英文短名>.md)：<适用>`；在 index.md「文件」一节该体裁下加一行 `  - [<类型名>](genres/<体裁>/<英文短名>.md)`。除「适用」外还写不出内容的类型不建文件。

## 范文

范文是作者圈出来、要写稿时照着学的亲笔文字：一段连续的段落，或作者整篇都认可的文章。放在 `genres/<体裁>/examples/<英文短名>.md`，一段或一篇一个文件，推文一组一个文件。只属于某个类型的从类型文件「范文」一节链接，其余从 default.md「范文」一节链接。文件开头：

```markdown
# <文章标题；段落写它讲什么>

- 题材：<类型和主题，如「踩坑教程：Vertex AI 开通和调用」>
- 学什么：<这篇示范的推进方式、段落写法，几条>
- 不照搬：<经历、数据、价格、命令、错字、文档腔、固定说法>
- 来源：<原文路径或链接>

---

<作者圈出的段落或整篇正文，照原样，去掉 frontmatter>
```

正文一个字都不改；错字、文档腔和与规则相反的写法记进「不照搬」。收哪一段由作者定，不替作者从整篇里挑。default.md 和每个类型各收一两篇，题材各不相同；已有的范文和新的题材重复时，把新旧给作者看，由作者定换哪篇。

## candidates.md

候选是还没定的写法：写稿 skill 追加的作者手改和原话，以及入档时作者说先不定的条目。格式见 archive-format.md「candidates.md」一节，文件开头的格式说明留着不动。

- 来源写稿件标题或路径。判断同一种改法是否出现在两篇稿子时看它。
- 作者搁置的条目下加一行「待问：……」。

## 工作流

### 1. 读档案

读项目配置里 `Writing style profile` 或用户消息给出的 index.md，再读它「文件」一节列出的全部文件、default.md 和类型文件链接的范文和 candidates.md。找不到 index.md 时请用户先运行 `/writing-style-setup`，到此为止。再读本 skill 的 [archive-format.md](references/archive-format.md)。

完成标准：index.md 列出的文件、范文、candidates.md 和 archive-format.md 都已读过。

### 2. 收材料

处理用户这次给的材料（改稿、原话、亲笔稿、旧的风格文件、别人整理的偏好），以及 candidates.md 里的全部条目；带「待问：」的在第 4 步再问一次。旧的风格文件和别人整理的偏好拆成单条，逐条找作者的原话或手改。重复的条目只留一条；同一种改法出现在几处的合成一条，写明出现在哪几篇稿子。一条手改里有几处无关的改动时，按改动拆开，每条只截改动所在的分句。用户只给终稿时，从对话或版本管理里找 agent 交付的上一版作改前，找不到就请用户提供。

作者给整篇亲笔稿、没说要哪些时，不自己从里面提炼规则：把看到的写法列成问题，在第 4 步问作者哪些是想留的。作者删掉的词和短语单独列出，作为禁用词表的材料。

每条标出依据类别；只有线索、没有依据的，记下要问作者的问题。

完成标准：每条都有依据类别，或有一个待问的问题。

### 3. 定去向

每条选一个或几个去向：

- **新规则**：原话说的是作者一贯的写法，不只针对这一篇；或同一种改法出现在两篇不同的稿子里（candidates.md 已有同类条目，或已有规则的例子里有同类改法），列进第 4 步由作者确认。按 archive-format.md「放哪」定位置。材料里没有例子的，在第 4 步向作者要一句改前改后或亲笔；作者给不出时照样写入，不编例子。口头习惯的规则没有例子时，再问一行「适用」：这个说法用在哪里。
- **改已有规则**：加一组例子；材料和规则冲突时，先缩窄（改「适用」，或改写成各管一处的两条），作者确认这条规则不再要时才删。已有同类例子、或新的比旧的更典型时，把新旧给作者看，由作者定换不换。
- **类型或范文**：按「类型文件」「范文」两节判断。
- **候选**：只出现一次的手改，和只给方向、作者没说是一贯偏好的原话，列进第 4 步问作者，默认留在 candidates.md。
- **不收**：只针对这一篇的内容改动（换例子、改数字、补事实）、模型默认就会这么写的、交稿流程和平台运营、数据表现。

范文里和规则相反的写法记进它的「不照搬」。

完成标准：每条都有去向，或已列进给作者的问题。

### 4. 问作者

把第 2、3 步的问题合成一份清单，按「这些是不是你写的或认可的」「这是你一贯的写法，还是只针对那一篇」「放哪一节」「和已有规则说法相反，按哪个」「例子和范文换不换」「这条规则有没有一句例子」分组，每条附上你的默认处理。作者没有反对的按默认处理写入；作者说先不定的，留在 candidates.md。问题多时分批问。

完成标准：每个问题都有结果：按默认处理、按作者的改法，或作者说先不定。

### 5. 写入并交付

按答复写入档案：

- 规则按 archive-format.md 写进对应文件，原地改写，不留旧说法。
- 新类型和范文按对应两节建文件、加链接，index.md「文件」一节和档案里的文件逐个对上。
- 处理过的候选从 candidates.md 删掉；作者说先不定的留下，加一行「待问：……」。

用户要求整理，或这次迁移了大批材料时，再把档案整体过一遍：同一意思写在两处的合并，放错文件或节的移走，规则和例子、范文说法对不上的列给作者，candidates.md 整份给作者过目，作者说删的删。

交付一份变更摘要，按类分组：新增、改写、缩窄、删除的规则（文件、节和规则名），新增和替换的例子、类型和范文，候选新增和升级的条目，不收的条目按原因归并。档案里还没有例子的规则列在摘要末尾，作者之后有合适的句子时再补。

完成标准：摘要里的每处改动都已在档案里；本次处理的候选已从 candidates.md 删掉，或带「待问：」。

## 校准

用户要求校准时做：用一篇亲笔稿检验档案能不能让写稿 skill 写出作者的写法。

### 1. 列素材

请用户指定一篇不在范文里的亲笔稿。从原文列素材清单：事实、数据、经历、观点，每条用自己的话写。

完成标准：原文的事实、数据、经历和观点都在清单里，每条都是转述。

### 2. 重写

开子代理，只给它素材清单、index.md 的路径和体裁，让它按 index.md 的使用说明读档案，写一篇同体裁的稿子，要和作者确认的地方按素材清单自己定。环境不支持子代理时告诉用户，到此为止。

完成标准：拿到一篇同体裁的完整重写稿。

### 3. 列差异

在本会话对比重写稿和原文，按结构、段落、句子三层列差异，去掉内容上的差异，如素材取舍和事实多少。

完成标准：三层都已对比，每条差异写明两边的位置和引文。

### 4. 归类

每条差异归一类：档案没写到、写了没照做、规则和原文相反。档案没写到的，建议加规则、例子或类型；规则和原文相反的，建议缩窄或改写规则；写了没照做的，记下哪条规则没被遵守，看它是不是放错了节、做法写得不清楚。

完成标准：每条差异都有一类，以及对应的建议或记录。

### 5. 确认并写入

把建议和没被遵守的规则一起给作者看。作者确认的建议按工作流第 5 步写入。

完成标准：每条差异都有去向，并经作者确认。
